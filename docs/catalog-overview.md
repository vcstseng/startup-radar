# Startup Radar：4,085 筆全貌總覽

這份總覽涵蓋全部 4,085 筆 AI 入選紀錄，保留每個原始 ID。現在的主要輸出是全量網站資料，不再只以先前 3 個主題代表全貌。尚未去重、補查官網或建置網站。

## 先看什麼

- 產業／客群：25 個大類。
- 問題／工作：22 個大類。
- 解法形式／技術：28 個大類。
- 每個維度另列「原始資訊不足」及「其他已描述／待歸類」。
- 三組交叉分布：產業 × 工作、產業 × 解法、工作 × 解法。

大類依既有人工細 tags 歸納，採穩定英文 ID 與中文名稱；允許一筆落入多個大類。這是可回查的第一版大分類，不是對全量原文重新人工驗證。沒有把工作、客群或方法從別的維度補進來。

工作方面，493 筆原本沒有 tags，196 筆是有細 tags 但尚未歸類，另外 216 筆部分待歸類。這三種情況分開保存，不用推測補滿。

## 如何探索交叉分布

先選客群，再看它有哪些工作；或先選工作，再比較不同產業使用的解法。每個格子的數量是兩邊 ID 集合的交集，並附少量示例 ID。分類索引可取得全部對應紀錄，不只示例。

三組表各有 532、607、584 個非零格子，包含資訊不足與待歸類格子。格子與列欄也可重疊，不可累加當作不同公司總數。

篩選時：同一維度多選採 OR，不同維度採 AND；例如「醫療或生技」與「財務收付款」的交集。清除某維度選項代表不限制，不代表只看未知。篩選後數量要依 ID 集合重算，不能沿用未篩選總數。

## 本次 review 與限制

本次規則針對既有細 tags，不從公司名稱、網址或其他維度推定功能。已檢查並排除幾類誤收：視覺化不是電腦視覺；軟體採購不是軟體開發；模型／車輛／土壤健康診斷不是醫療照護；服務機器人不是專業服務交付。

解法大類包含技術、能力及交付形式，以 kind 註明。因此 SaaS、平台、agents 不等於已驗證技術能力；「服務、顧問與經紀」也包含資料與運算服務，不能直接當作 AI 服務營運公司數。示例採固定排序與來源分散，避免同名反覆出現，不作熱門或品質排名。

網址有 3,598 筆提供但未連線驗證、477 筆缺漏、1 筆格式不合、9 筆是共用 Antler 來源網址。後三類 website 留 null；不自行找官網。原文與上游欄位仍保留於固定 raw，未刪資料。

來源偏重加速器名錄，且尚未去重。沒有一致時間、採用率或營收資料，不能由這份分布推定市場需求、成長率、台灣落差或商業成功。先前 7 個主題與 3 題 review 保留為探索例子，不用它們限制全量分類。

## 重建與驗證

`python scripts/analyze/build_catalog.py` 重建資料；`python scripts/analyze/validate_catalog.py` 核對 schema、完整 ID、原始摘要與原文、全部分類索引、交叉格子、分母及分類邊界。

manifest.json 保存來源、規則、schema、產生程式與所有輸出雜湊；build_id 識別這次資料建置。原始資料、21 輪批次及先前彙整輸出保持原樣。
