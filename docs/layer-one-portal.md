## 本輪完成

- 三個平行入口：產業／客群 25 類、問題／工作 22 類、解法 28 類；分類及數量取自既有 catalog。
- 可從任一維度開始；同欄多選為 OR，跨欄為 AND，不要求選滿三欄。
- 顯示符合的紀錄總數、已選條件、逐一移除、全部清除，以及零筆組合提示。
- 選項旁不顯示筆數，只保留上方「同時符合目前條件：N 筆」。可選分類仍依其他兩欄計算，忽略本欄已選條件，以保留同欄 OR 擴選；沒有改成全欄只取最終交集。
- 依使用者最新指示移除搜尋功能。資料不足與待歸類另列，不混入 25／22／28。
- 未選且交叉筆數為 0 的分類隱藏；已選分類即使變成 0 仍保留，可從原列或條件列取消。取消、清除或返回後重新計算並恢復相關選項；每欄標示全量分類數與目前顯示數。
- 「回上一步」撤回最近一次條件變更，包含清除／移除；瀏覽器上一頁／下一頁同步。歷史紀錄保存條件、手機目前維度及捲動位置；初次直接進入不會導向外站。
- 條件、筆數及操作區在捲動時保持可見；三欄標題對齊，已選條件多時可在條件區內捲動。
- 三欄標題改為「服務誰？」「解決什麼工作？」「採用什麼做法？」；條件區標示「目前選擇」，返回操作改為「撤回上次選擇」。固定說明：「每欄可以多選，符合其中一項即可；不同欄的條件則必須同時符合。不必選滿三欄。」
- 首屏先說目的：「AI 新創正在解決哪些問題？」交代 4,085 筆 AI 相關新創紀錄，並以「醫療＋語音」說明如何開始；不以內部的 Layer 或 tags 術語要求使用者理解產品。
- 保留明顯的「查看結果 →」入口；使用者明確選擇本輪只調整 Layer 1，因此按鈕暫停用並標示「結果頁尚未開放」。單選、多選皆採同一組條件，待 Layer 2 討論後接上。
- 選取條件寫入網址，可複製、重新整理還原及配合瀏覽器上一頁／下一頁。
- 桌面三欄並排；手機以三個按鈕切換維度，保留跨欄選取。
- 載入、錯誤重試、鍵盤焦點與即時筆數狀態。

筆數是尚未去重的來源紀錄，分類可以重疊；不表示採用率、成長率、需求或市場機會。

## 本機執行

在 `D:\startup-radar\web` 執行：

```powershell
npm ci
npm run dev -- --port 4173 --strictPort
```

開啟 http://127.0.0.1:4173/ 。已有相依套件時可直接執行第二行。關閉預覽可在啟動的終端按 Ctrl+C。本機預覽與公開網站分開；預覽可供後續 review，不影響 GitHub Pages。

檢查與建置：

```powershell
npm test
npm run build
```

建置結果在 `web/dist/`。如要檢查建置版本，執行 `npm run preview -- --port 4173 --strictPort`。子路徑部署時應設定 Vite base；目前使用根路徑。

## 資料及未來銜接

資料契約沿用 `docs/website-data-contract.md`，來源為 `data/processed/catalog/v1/`。資料 schema、原始快照、正式批次及 21 份詳情未改。經使用者同意，針對明確的聊天機器人誤分類修正衍生大類規則並重建 catalog，分類版本為 `catalog-1.0.1`；共 12 筆移除 robotics 大類，該類 64 → 52 筆。原本的逐筆 tags 保留。變更清單見 `reviews/2026-11-02-robotics-correction.json`，不代表其他大類已完成語意複核。

開發預覽只透過受限路徑讀取 catalog JSON。建置時 `scripts/prepare-data.mjs` 複製允許的五份索引／摘要資料及 21 份分批詳情到公開資料目錄，不複製 raw 或內部稽核紀錄。Layer 1 啟動只載入 index、taxonomy、facets、summary，不預先下載全量 records 或詳情。

條件網址約定：

```text
/?industry=healthcare&solution=voice-conversation
```

`industry`、`work`、`solution` 均使用穩定分類 ID；同欄多選重複 query key。未知 ID 忽略、重複 ID 去除，輸出按 ID 排序。不加入搜尋條件。

後續 Layer 2 可沿用 `src/lib/filter.ts` 的選取及符合 ID，按需讀 records 顯示結果；Layer 3 可按 `detail_file` 及 ID 讀取既有詳情。兩層各用一個共用模板，不預建分類組合或逐家公司頁。本輪僅保留停用的結果入口，未建立結果列表、詳情頁或可用跳轉。

批次蒐集 → 理解 → 驗證 → 保存 → 發布是未來資料更新管線；本輪完成的是使用端入口。排程、增量 AI、外部查證與 99 Problems 比對未實作。
